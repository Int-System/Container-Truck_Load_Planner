# Container & Truck Load Planner

ระบบวางแผนจัดเรียงสินค้าในตู้คอนเทนเนอร์และรถกระบะ/รถบรรทุกตู้ทึบ เป็นเว็บแอป HTML ล้วน
ไม่ต้องติดตั้งหรือ build อะไร มีโหมดจัดเรียงอัตโนมัติ (Auto Pack), จัดวางเองใน 3D (Manual) และแบบผสม (Hybrid)
แสดงผลได้ทั้ง 3D และ 2D (มุมบน / ด้านข้าง / มองจากประตู) พร้อมรายงานและการเปรียบเทียบตัวเลือกตู้/รถ

## วิธีรัน

**วิธีที่ 1: ดับเบิลคลิก `index.html`** ใช้ได้ทันทีกับ Chrome, Edge หรือ Firefox (Web Worker สร้างจาก Blob จึงทำงานได้แม้เปิดแบบ `file://`)

**วิธีที่ 2: ผ่าน local server** (แนะนำ)
```bash
python -m http.server 8765
```
แล้วเปิด <http://localhost:8765/>

> ต้องต่ออินเทอร์เน็ตครั้งแรก เพื่อโหลด three.js (3D), SheetJS (Excel) และฟอนต์ Sarabun จาก CDN
> ถ้าออฟไลน์ หน้า 2D, Auto Pack, รายงาน และ CSV ยังใช้งานได้ปกติ

### ทำไมใช้ HTML ล้วน แทน React + TypeScript + Vite

คุณขอเป็น "แบบ HTML ที่ใช้งานได้จริง" และเครื่องนี้ไม่มี Node.js จึงเลือก Vanilla JS แยกเป็นโมดูลตามโครงสร้างที่กำหนด
ข้อดีคือเปิดใช้ได้ทันทีโดยไม่ต้อง build ส่วน engine เขียนเป็น pure functions ที่ไม่พึ่ง UI
ถ้าภายหลังจะย้ายไป React/TS/Zustand ก็ยกโฟลเดอร์ `src/engine` ไปได้ทั้งชุด

**PDF:** ใช้หน้ารายงาน HTML แล้วสั่ง "พิมพ์ → บันทึกเป็น PDF" แทน jsPDF
เพราะ jsPDF ต้องฝังฟอนต์ไทยเอง วิธีนี้ได้ภาษาไทยที่ถูกต้อง พร้อมภาพ 3D และ SVG 2D ที่คมชัด

## อัลกอริทึม Auto Pack

เลือกใช้ **Empty Maximal Spaces (EMS) + Block building + GRASP** (แนวทางเดียวกับงานวิจัยของ Parreño et al. ซึ่งเป็นกลุ่มที่ได้ผลดีที่สุดใน benchmark BR ของปัญหา container loading)

1. เก็บพื้นที่ว่างเป็นรายการกล่องว่างที่ใหญ่ที่สุด (maximal spaces) ของจะถูกวางลงในพื้นที่ว่างเท่านั้น จึง**ไม่มีวันชนกัน**
2. ในแต่ละรอบ เลือกพื้นที่ว่างที่ใกล้มุมหน้า-ล่าง-ซ้ายที่สุด ได้ 2 แบบ:
   - `wall` (เรียงลำดับตาม y, z, x) สร้างเป็นกำแพงจากหน้าตู้ไปหาประตู
   - `layer` (เรียงลำดับตาม z, y, x) ปูพื้นทีละชั้น
3. สร้าง **block** คือสินค้า SKU เดียวกันวางทิศเดียวกัน nx × ny × nz ชิ้น จำนวนต่อแกนได้จากค่าสูงสุด บวกกับค่าที่คำนวณแบบ 1-D fill
   (เช่น 239 = 2×40 + 5×30) ทำให้ผสมการหมุนหลายทิศจนเต็มช่องได้ วิธีนี้ทำให้สินค้าชนิดเดียวกันหลายร้อยชิ้นคำนวณได้เร็วมาก
4. ให้คะแนน block จากปริมาตร (หรือจำนวนชิ้น) บวก look-ahead ที่ประเมินว่าพื้นที่ที่เหลือจะเติมได้อีกเท่าไร
5. ตรวจเงื่อนไขทุกครั้ง:
   - ฐานรองรับขั้นต่ำ (ค่าเริ่มต้น 75%) และสินค้าเปราะบาง/ห้ามซ้อน
   - จำนวนชั้นซ้อนสูงสุด และน้ำหนักทับ (คำนวณส่งต่อลงไปถึงชั้นล่างสุด)
   - ของหนักต้องไม่อยู่บนของเบา และน้ำหนักไม่เกินพิกัดบรรทุก
   - ของที่ยื่นออกไปต้องไม่ไปทับของเปราะบางที่วางทีหลัง
   - ในโหมดลำดับขนถ่าย ของที่ลงก่อนต้องไม่ถูกของที่ลงทีหลังขวางทางประตู
6. **GRASP**: รันแบบกำหนดผลตายตัว 4 รอบก่อน จากนั้นสุ่มเลือก block ในกลุ่มคะแนนสูงสุด top-δ วนจนหมด time budget แล้วเก็บผลที่ดีที่สุดตามเป้าหมาย

**เป้าหมายที่เลือกได้**
- **จำนวนชิ้นมากสุด:** ให้คะแนนตามจำนวนชิ้น
- **ใช้พื้นที่คุ้มสุด:** ให้คะแนนตามปริมาตร
- **สมดุลสุด:** ใช้ปริมาตรก่อน (ปัดเป็นช่วงละ 0.5%) แล้วเลือกผลที่ CoG ใกล้กึ่งกลางที่สุด และเลื่อนทั้งกองไปไว้กลางตู้ถ้ายังมีที่ว่าง
- **ลำดับขนถ่าย:** โหลดกลุ่มที่ลงทีหลังก่อน (เข้าไปลึกสุด) และตรวจว่าทางไปประตูไม่ถูกขวาง

ทุกเป้าหมายจะเลือกวาง block ชิดซ้ายหรือขวาของพื้นที่ว่าง เพื่อให้ CoG ด้านข้างอยู่กลางตู้

ลำดับการโหลด (ใช้ในแอนิเมชันและรายงาน) คำนวณด้วย topological sort: ของที่เป็นฐานรองรับจะมาก่อนเสมอ แล้วเรียงจากหน้าตู้ไปประตู และจากล่างขึ้นบน

## ช่องประตู · น้ำหนักลงเพลา · คลังสินค้า

**ช่องประตู**
- ทุก preset มีขนาดช่องประตูจริง ซึ่งเล็กกว่าขนาดภายใน เช่น ตู้ 20' ช่องประตู 234 × 228 ซม. แต่ภายในสูง 239 ซม. แก้ค่าได้ในแผงตู้/รถ
- Auto Pack ใช้เฉพาะทิศที่สินค้ายกผ่านประตูได้ ถ้าไม่มีทิศไหนผ่านได้ สินค้านั้นจะไม่ถูกใส่ และระบบแจ้งเหตุผล
- ในโหมดจัดวางเอง validator จะเตือนชิ้นที่ใหญ่เกินประตู (`doorClear`)
- รายการสินค้าแสดงป้าย "เกินประตู" ส่วนภาพ 3D และมุมมองจากประตูแสดงขอบช่องประตูจริง

**น้ำหนักลงเพลา** (`E.axleLoads` ใน `src/engine/cog.js` และ `src/data/vehicles.js`)
- คำนวณแบบคานรับน้ำหนักจากน้ำหนักและตำแหน่งสินค้าทุกชิ้น
  - รถบรรทุก: ตู้วางบนเพลาหน้าและเพลาหลัง
  - หัวลาก + หางพ่วง (เมื่อเลือกเองสำหรับตู้คอนเทนเนอร์): ตู้วางบนจานลากและกลุ่มเพลาหางพ่วง แล้วแบ่งน้ำหนักที่จานลากลงเพลาหน้าและเพลาขับของหัวลาก
- ตำแหน่งเพลามาจากข้อมูลชุดเดียวกับโมเดลรถ 3D จึงตรงกับภาพ
- เตือนเมื่อเพลาใดเกินพิกัด, น้ำหนักรวมรถ (GVW) เกิน หรือเพลาหน้าเบากว่า 20% ของน้ำหนักรวม
- **น้ำหนักรถเปล่า พิกัดเพลา และ GVW เป็นค่าเริ่มต้นโดยประมาณ** (เช่น รถ 6 ล้อ GVW 15 ตัน, 10 ล้อ 25 ตัน, หัวลาก+หางพ่วง 50.5 ตัน) แก้ได้ที่ ตู้/รถ → ตัวเลือกขั้นสูง → น้ำหนักลงเพลา และควรตรวจกับเล่มทะเบียนรถหรือกฎหมายที่ใช้จริง

**คลังสินค้า (SKU Master)**
- เก็บไว้ในเบราว์เซอร์ (localStorage) เปิดครั้งแรกจะมีสินค้าตัวอย่างให้
- เปิดจากปุ่ม "คลังสินค้า" แล้วค้นหา ติ๊กเลือกหลายรายการพร้อมใส่จำนวน ถ้างานมีรหัสเดียวกันอยู่แล้ว ระบบจะบวกจำนวนเพิ่ม
- บันทึกลงคลังได้ทีละรายการ, ทั้งหมดในงาน หรือติ๊ก "บันทึกลงคลังสินค้าด้วย" ในฟอร์ม
- พิมพ์รหัสสินค้าในฟอร์มแล้วระบบจะกรอกข้อมูลที่เหลือจากคลังให้
- นำเข้า/ส่งออกคลังเป็น CSV ได้ (ใช้รูปแบบเดียวกับไฟล์นำเข้าสินค้า)

## งานส่งออก · หน้างาน · เงื่อนไขพิเศษ (รอบ 4)

| ฟีเจอร์ | วิธีใช้ / การทำงาน |
|---|---|
| **VGM + ข้อมูลส่งออก** | ตู้คอนเทนเนอร์มีน้ำหนักตู้เปล่า (Tare) และ Max Gross ใน preset (แก้ได้ในตัวเลือกขั้นสูง) แผงสรุปแสดง VGM = Tare + สินค้า + วัสดุยึด และเตือนเมื่อเกิน Max Gross ปุ่ม "ข้อมูลส่งออก / VGM" ใช้กรอกเลขตู้ (ตรวจ check digit ตาม ISO 6346), เลขซีล, Booking, เรือ, ท่าเรือ, ผู้ส่ง, ผู้รับ และผู้รับรอง ข้อมูลทั้งหมดไปอยู่ในรายงาน PDF พร้อมคำรับรอง VGM ตาม SOLAS |
| **ใบส่งของ (Packing list)** | เมนูส่งออก → "ใบส่งของ" หรือปุ่มใต้ตาราง SKU ในแผงสรุป ใบส่งของสร้างจากสินค้าที่วางในรถ/ตู้จริง ถ้ามีหลายจุดส่งจะแยกใบตามจุด และพิมพ์ต้นฉบับ+สำเนาได้ มีโลโก้บริษัท ทะเบียนรถ คนขับ เลขตู้/ซีล รายการ จำนวน น้ำหนัก ปริมาตร สินค้าค้างส่ง และช่องลงชื่อผู้ส่ง/คนขับ/ผู้รับ |
| **ใช้งานออฟไลน์ (PWA)** | ต้องเปิดผ่าน http(s) อย่างน้อย 1 ครั้งเพื่อให้ระบบเก็บไฟล์ไว้ (เปิดจาก `file://` จะใช้ออฟไลน์ไม่ได้) จากนั้นใช้ได้แม้ไม่มีเน็ต และติดตั้งเป็นแอปบนแท็บเล็ต/มือถือได้ ไฟล์ของแอปโหลดแบบ network-first จึงได้เวอร์ชันล่าสุดเสมอเมื่อออนไลน์ ไม่ต้องกด Ctrl+F5 **เมื่ออัปเดตโค้ด** ให้เปลี่ยน `?v=` ใน `index.html` และ `VERSION` ใน `sw.js` |
| **Auto Pack จัดน้ำหนักลงเพลา** | (ตัวเลือกขั้นสูง → "จัดให้น้ำหนักลงเพลาไม่เกินพิกัด", เปิดไว้เป็นค่าเริ่มต้น) ระบบเลือกแบบจัดเรียงที่ไม่เกินพิกัดเพลาก่อน ถ้ายังเกินจะเลื่อนสินค้าทั้งกองตามความยาวตู้และแจ้งให้ใช้ไม้ค้ำ |
| **เช็กลิสต์โหลด (มือถือ)** | แท็บลำดับการโหลด → "เช็กลิสต์โหลด" เปิดหน้าจอเต็มที่มีปุ่มใหญ่ ให้นับจำนวนต่อ SKU ทีละขั้น มีผังมุมบนของขั้นนั้น บันทึกชื่อผู้โหลดและเวลาเสร็จแต่ละขั้น สแกนบาร์โค้ดด้วยกล้องได้ (Chrome บน Android) ระบบจำความคืบหน้าไว้ และส่งออกบันทึกเป็น CSV ได้ |
| **ใบงานโหลดทีละขั้น** | พิมพ์หน้าละขั้น (A4 แนวนอน) ภาพ 3D แสดงขั้นปัจจุบันเป็นสีปกติ ขั้นก่อนหน้าเป็นสีจาง พร้อมผังมุมบน รายการสินค้า และช่องลงชื่อ |
| **ชุดรถผสมที่ถูกที่สุด** | เปรียบเทียบ → "หาชุดรถผสมที่ถูกที่สุด" เช่น 2,400 กล่องได้ 1×40' + 1×20' = 37,000 บาท ถูกกว่าใช้ 40' 2 ตู้ (44,000 บาท) เปิดดูแต่ละคันได้ในแท็บหลายตู้ ถ้าไม่ได้ใส่ค่าขนส่ง ระบบจะเลือกชุดที่ปริมาตรรวมน้อยที่สุดแทน |
| **ถังเรียงสลับฟันปลา** | ถังทรงกระบอกตั้งบนพื้นจะเรียงแบบ hexagonal เมื่อใส่ได้มากกว่า เช่น ถัง ⌀50 ซม. ในตู้ 20' ได้ 52 ใบ แทน 44 ใบ (ถัง ⌀58 ซม. ในตู้กว้าง 235 ซม. ไม่ได้เพิ่ม ระบบจึงเรียงแบบตารางตามปกติ) การตรวจชนกันของถังคิดตามวงกลม |
| **เงื่อนไขพิเศษ** | ตั้งในฟอร์มสินค้า → "เงื่อนไขพิเศษ" มีดังนี้ |
| ↳ กลุ่มแยกห่าง/DG | สินค้าต่างกลุ่มต้องห่างกันตามระยะที่ตั้งไว้ (ค่าเริ่มต้น 150 ซม.) |
| ↳ โซนอุณหภูมิ | แช่แข็งอยู่หน้าสุด (ใกล้เครื่องทำความเย็น) → แช่เย็น → อุณหภูมิปกติ |
| ↳ ด้านสอดงา (พาเลท) | บังคับให้ด้านสอดงาหันหาประตู |
| ↳ พื้นรับน้ำหนัก | ตั้งเป็น กก./ตร.ม. ต่อตู้/รถ ระบบจำกัดความสูงของกองให้ไม่เกิน |
| **สี/โลโก้หัวรถ + มุมกล้อง "มองหัวรถ"** | แผงการแสดงผล → เลือกสีหัวรถและอัปโหลดโลโก้ (ติดที่ประตูทั้ง 2 ข้าง) แถบมุมกล้องมีปุ่มรูปรถสำหรับมองหัวรถ |

**ภาพ 3D รองรับงานใหญ่ (InstancedMesh):** กล่องทั้งหมดวาดรวมเป็นชุดเดียว (กล่อง / ถัง / ฐานพาเลท อย่างละ 1 ชุด และเส้นขอบรวมเป็นเส้นเดียว) แทนการวาด 2 ครั้งต่อกล่อง งาน 3,000 กล่อง (มีในเมนูตัวอย่างข้อมูล) ใช้เวลาวาดประมาณ 1.2–1.4 มิลลิวินาทีต่อเฟรม การคลิกเลือก ลาก ซ่อนตาม SKU/ชั้น/ตัดความยาว สีแดงตอนชน และแอนิเมชันลำดับโหลดทำงานเหมือนเดิม ส่วนกล่องที่ซ่อนอยู่จะถูกย่อขนาดเป็นศูนย์แทนการลบ

**เมื่อแก้ไขโค้ด:** ต้องเปลี่ยนเลข `?v=` ใน `index.html` (ทุกบรรทัด) และ `VERSION` ใน `sw.js` ทุกครั้ง ถ้าไม่เปลี่ยน เบราว์เซอร์อาจใช้ไฟล์เก่าที่จำไว้ (ตอนทำ E2E เจอปัญหานี้จริง) เวอร์ชันปัจจุบันคือ 4.2.1

ค่าเริ่มต้นใหม่ (Tare, Max Gross, พื้นรับน้ำหนัก: ตู้ 3,000 / รถ 1,500–3,000 กก./ตร.ม.) เป็นค่าประมาณ แก้ได้ทั้งหมด

## คู่มือผู้ใช้

คู่มือฉบับเต็มสำหรับผู้ใช้ใหม่ (ภาษาไทย มีภาพประกอบ) เปิดได้จากปุ่ม **?** ที่แถบด้านบนของโปรแกรม หรือกดปุ่ม `?` บนคีย์บอร์ด หน้าคู่มือคือ `manual.html` รองรับมือถือและแท็บเล็ต และใช้แบบออฟไลน์ได้ เพราะ service worker เก็บไฟล์คู่มือไว้ด้วย ในหน้าคู่มือมีปุ่มดาวน์โหลด PDF (`docs/LoadPlanner-Manual-TH.pdf`)

- **ไอคอน ? เล็ก ๆ** ข้างหัวการ์ด 1–3 แผงสรุป แถบเครื่องมือจัดวางเอง และหน้าต่างต่าง ๆ จะเปิดคู่มือตรงหัวข้อนั้น (`LP.helpLink` → `manual.html#<id>` โดย id ของแต่ละหัวข้อกำหนดไว้ใน `SLUGS` ของ `docs/build_manual.py`)
- **ทัวร์แนะนำ** (`src/components/tour.js`) ขึ้นเองครั้งแรกที่เปิดโปรแกรม เปิดใหม่ได้ที่เมนูไฟล์ → ทัวร์แนะนำการใช้งาน หรือ `index.html?tour=1`
- **แกนและระยะ** (ปุ่มการแสดงผลบนภาพ 3D) เป็นตัวเลือกเสริม ไม่เปลี่ยนของเดิม มี 4 สวิตช์: ไอคอนแกน X/Y/Z มุมภาพ, จุด 0,0,0 + เส้นประบอกระยะ x/y/z ของกล่องที่เลือก (ช่อง x/y/z ในการ์ดจะมีสีและคำบอกว่าวัดจากไหน), ไม้บรรทัดตามขอบพื้น (เฉพาะโหมดจัดวางเอง/ทุกโหมด, ขีดทุก 10–100 ซม.) และลูกบาศก์มุมมอง ทั้งหมดวาดเป็นชั้น HTML/SVG ทับภาพ (`viewer3d.js` → `setAxes`) จึงไม่ติดไปในภาพที่พิมพ์ ค่าเก็บใน `localStorage` คีย์ `lp.axes` ค่าเริ่มต้นเปิดแกนกับจุด 0,0,0 ปุ่ม "ปิดทั้งหมด" กลับเป็นหน้าจอแบบเดิม
- **รูปแบบภาพ / ระบายสี / แอนิเมชัน** (ปุ่มการแสดงผล) เป็นตัวเลือกเสริมเช่นกัน ค่าเริ่มต้นเหมือนเดิม: แบบสมจริง = ตู้เหล็กลอน พื้นไม้ ประตูกางแนบผนัง เลขตู้บนคานประตู (`vehicle3d.js` → `realShell`, ตู้คอนเทนเนอร์เท่านั้น) + กล่องกระดาษมีเทปและป้ายสี SKU, พาเลทไม้ + ฟิล์ม, ถังมีลอน, คนเทียบขนาด 1.70 ม. (`src/components/cargo3d.js`) ผนังฝั่งที่บังกล้องถูกซ่อนอัตโนมัติ งานเกิน 1,500 ชิ้นจะไม่วาดป้ายข้างกล่องและเงาสินค้า · ระบายสีตาม SKU / น้ำหนัก (สเกล log) / จุดส่ง / เปราะบาง ใช้ทั้ง 3D และ 2D (`LP.cargoColor` ใน `viewer2d.js`) พร้อมคำอธิบายสี · เล่นลำดับโหลดแบบกล่องเลื่อนเข้าจากประตู (`viewer3d.animateIn`) ความเร็ว 1×/2×/4× ค่าเก็บใน `localStorage` คีย์ `lp.style`, `lp.person`, `lp.colorBy`, `lp.animate`
- **วัสดุยึดที่แนะนำ** (`src/engine/dunnage.js` → `E.dunnagePlan`) หาช่องว่างหลังจัดเรียง: ช่องหน้าประตู → ไม้ค้ำขวาง, ช่องไม่เกิน `bagMaxGap` (45 ซม.) → ถุงลมตามขนาดที่มี, ช่องที่กว้างกว่า → คำเตือนให้เติมพาเลทเปล่า/ไม้ ช่องตามผนังคิดตลอดช่วงที่มีช่องโดยใช้จุดที่แคบที่สุด (ถังวางสลับฟันปลาจึงไม่ได้ถุงลมทุกแถว) และไม่สนช่องสั้นกว่า 60 ซม. แสดงในแผงสรุป (คลิกเพื่อดูใน 3D) รายงาน PDF และใบงานโหลด (นับเฉพาะชิ้นในช่วงของขั้นนั้น) ตั้งค่าได้ที่ปุ่มตั้งค่าในส่วนนี้ (เก็บใน `settings.dunnage` ของงาน) ปุ่ม "ใช้น้ำหนักนี้ใน VGM" ใส่น้ำหนักลงข้อมูลการส่งออก
- **สรุป 1 หน้า** (`quickref.html` และ `docs/LoadPlanner-QuickRef-TH.pdf`) สำหรับพิมพ์ติดหน้างาน เปิดจากเมนูไฟล์ ถ้าแก้ไขต้องพิมพ์ PDF ใหม่ด้วยคำสั่งเดียวกับคู่มือ

วิธีแก้ไขคู่มือ:

1. แก้ `docs/manual.md` ภาพประกอบอยู่ใน `docs/manual/` บรรทัดภาพเขียนแบบ `[image: ชื่อภาพ]` และต้องมีชื่อภาพใน `IMAGES` ของ `docs/build_manual.py`
2. รัน `python docs/build_manual.py` เพื่อสร้าง `manual.html` ใหม่
3. สร้าง PDF ใหม่ โดยรันเซิร์ฟเวอร์ แล้วสั่ง Edge หรือ Chrome แบบ headless:
   `msedge --headless=new --no-pdf-header-footer --print-to-pdf=docs/LoadPlanner-Manual-TH.pdf http://localhost:8765/manual.html`
   หรือเปิด `manual.html` แล้วกด Ctrl+P → บันทึกเป็น PDF
4. เปลี่ยนเลขเวอร์ชันใน `index.html` และ `sw.js`

## คู่มือใช้งานย่อ

1. เลือกตู้/รถ (แก้ขนาด น้ำหนักบรรทุก และค่าขนส่งต่อเที่ยวได้ และบันทึกเป็น Preset ของตัวเองได้)
2. เพิ่มสินค้า หรือนำเข้า CSV/Excel
3. เลือกเป้าหมาย แล้วกด **จัดเรียงอัตโนมัติ** ถ้าใส่ไม่ครบ ระบบจะแนะนำว่าต้องใช้กี่ตู้/คัน และตู้ขนาดไหนที่ใส่ได้ครบใน 1 ตู้ โดยดูรายละเอียดแต่ละตู้ได้ที่แท็บ **หลายตู้**
4. โหมด **จัดวางเอง** มีปุ่มลัดดังนี้:

   | ปุ่ม | การทำงาน |
   |---|---|
   | ลากเมาส์ | ย้าย (snap กริด / ผนัง / สินค้า + แรงโน้มถ่วง) |
   | `R` | หมุน |
   | `T` | พลิก |
   | `PgUp` / `PgDn` | ยกขึ้น / ลดลงทีละชั้น |
   | ลูกศร | เลื่อนทีละช่องกริด (กด Shift = ทีละ 1 ซม.) |
   | `Ctrl+D` | คัดลอก |
   | `Del` | ลบ |
   | `L` | ล็อก |
   | `Ctrl+Z` / `Ctrl+Y` | ย้อนกลับ / ทำซ้ำ |

   ถ้าชน ล้นตู้ หรือลอย กล่องจะเป็นสีแดงทันที
5. **Hybrid:** ล็อกชิ้นที่ต้องการ แล้วกดจัดเรียงอัตโนมัติ ระบบจะเติมรอบชิ้นที่ล็อกไว้
6. **ส่งออก:** PDF (พิมพ์), Excel (Summary/Cargo/Placements), CSV และบันทึก/เปิดโปรเจกต์เป็น JSON
7. **เปรียบเทียบ:** เลือกหลายตู้/รถ ระบบจะคำนวณจำนวนคันที่ต้องใช้ ค่าใช้จ่ายรวม และค่าใช้จ่ายต่อชิ้น แล้วไฮไลต์ตัวเลือกที่คุ้มที่สุด

## ข้อจำกัด / แผนต่อยอด

- ถังทรงกระบอกคำนวณด้วยกล่องที่ครอบรอบ (bounding box) ส่วน 3D และ 2D จะวาดเป็นทรงกระบอก
- การตรวจ CoG ใช้เกณฑ์ทั่วไป (ซ้าย-ขวา ±5%, หน้า-หลัง ±10%)
- น้ำหนักลงเพลาเป็นการคำนวณแบบคานรับน้ำหนักอย่างง่าย และใช้ค่าเริ่มต้นโดยประมาณ ส่วน Auto Pack ยังไม่ได้ปรับตำแหน่งสินค้าเพื่อให้น้ำหนักลงเพลาดีขึ้น (ทำได้แค่แจ้งเตือน)
- การตรวจช่องประตูถือว่ายกสินค้าเข้าในทิศเดียวกับที่วาง ไม่ได้คิดกรณีพลิกหรือหมุนสินค้าหลังเข้าตู้แล้ว
- ถ้าต้องการคำนวณงานหนักมากฝั่ง server (เช่น OR-Tools) ก็ส่งข้อมูล JSON รูปแบบเดียวกับ `E.pack()` ไปได้เลย
